# Blaster Configuration File (`blaster.yaml`)

This document outlines the default configuration structure generated by `blaster init`. It serves as the single source of truth for test targets, load parameters, authentication strategies, AI integrations, and reporting behaviors.

```yaml
version: "1.0"

project: "ecommerce-core"

target:
  # The directory where parsed endpoints are stored.
  parser: "blaster/endpoint"
  # Local file path or URL for the OpenAPI/Swagger specification.
  # If provided, the parser extracts and merges missing endpoints. If omitted, no parsing occurs.
  swagger: "[https://api.example.com/openapi.json](https://api.example.com/openapi.json)"
  # Overrides the base server URL defined in the OpenAPI spec.
  # If left blank, the default server from the spec is used.
  base_url: "[https://staging.example.com](https://staging.example.com)"

load:
  # Number of concurrent workers (threads) running simultaneously.
  concurrency: 100
  # Total number of HTTP requests to execute during the blast phase.
  requests: 10000

ignore:
  endpoints:
    - /login
    - /users  # Ignored to prevent corrupting/invalidating active session tokens during tests.
    - /health

fixed:
  # Global static fields. These key-value pairs will be universally injected 
  # into all requests where applicable. 
  # Note: Users can also use the `blaster parse` CLI to set specific fields 
  # to 'notchange' on a per-API basis.
  limit: 10000
  page: 1
  locale: vi

auth:
  # Authentication configuration. 
  # If active tokens are provided, the `accounts` and `login` blocks are skipped.

  # Optional: Load tokens from an external file.
  # tokens_file: "./blaster/tokens.yaml"
  
  # List of pre-provisioned, long-lived tokens (Highest priority).
  tokens:
    - ${ADMIN_TOKEN}
    - ${USER_TOKEN}

  # Optional: Load credentials from an external file.
  # accounts_file: "./blaster/accounts.yaml"
  
  # Fallback credentials used by the Warm-up Worker if no tokens are provided.
  accounts:
    - username: admin@example.com
      password: ${ADMIN_PASSWORD}
    - username: user@example.com
      password: ${USER_PASSWORD}

  # Automatic login execution strategy.
  login:
    url: "/api/login"                  # The authentication endpoint
    method: POST                       # HTTP Method
    body: json                         # Supported formats: json | form | multipart
    success_status: 200                # The expected HTTP status code for a successful login
    extract: "$.data.access_token"     # JSONPath expression to extract the token from the response
    inject:
      type: header                     # Injection target: header | query | cookie
      key: Authorization               # The target key name
      value: "Bearer {{token}}"        # The format string used to inject the extracted token

ai:
  # Supports OpenAI, Ollama, OpenRouter, or any OpenAI-compatible API endpoint.
  api: "${BLASTER_AI_API}"
  features:
    - smart_fuzzing
    - impact_analysis

output:
  # JUnit XML report, essential for CI/CD pipelines (GitHub Actions, GitLab CI).
  junit: "blaster/report.xml"
  # Visually rich static HTML report for QA and management review.
  html: "blaster/report.html"
  # Directory to persist state and execution metadata. 
  # Enables differential testing (running only modified APIs locally) and historical comparisons.
  cached: "blaster/cached"
